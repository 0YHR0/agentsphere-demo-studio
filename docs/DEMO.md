# 解决方案演示手册

## 一个场景串起来

客户项目简报 → AgentSphere 独立沙箱 → OpenClaw 整理交付摘要 → 等待人工确认时暂停 → Connect 恢复同一实例 → 检查资料 → 清理资源。

页面分为“基础能力”和“OpenClaw 场景”。基础能力可独立预制状态；OpenClaw 页面先介绍业务目标和准备项，再填写模型、CLI 和用户，并按 8 个业务步骤执行。点击步骤留在场景页面，展示对应 SDK 代码与结果。

## 三种讲解路线

| 客户关注点 | 建议选择的能力 | 自动准备 |
|---|---|---|
| 能否快速运行我的 Agent | OpenClaw 场景的 8 步业务流程 | 配置模型与网络后，按业务顺序现场执行 |
| 暂停后是否还能继续 | 恢复后检查文件 | 新建或复用实例、写文件、暂停、恢复 |
| 如何管理环境与资源 | 创建模板 → Build → Build 日志 → 删除模板 | 创建独立演示模板，保留外部模板 |

基础能力中，进入任意步骤时，先读“为这项演示准备什么”。如果希望现场从暂停状态开始讲，先点“仅准备状态”；准备完成后，“准备并演示”会重新检查前置状态，确保正式动作满足条件。

## Build 与日志

已有 Ready 模板用于即时创建沙箱；新建模板用于展示构建。构建通常需要数分钟，不会阻止用户切换到其他能力；同一时刻只运行一个后台操作。

日志可配置独立的 Template ID、Build ID；留空则查询本次演示模板。返回 `building` 时照实展示，空日志不等于完成。固定日志对象不属于本轮清理资源。

## 资源与失败处理

演示失败会保留状态和资源账本。可查看执行过程，修正配置后重试。已有自有沙箱到期时，普通演示可新建一个并明确记录；暂停恢复和文件校验过程中若原实例消失，会报错而不是偷偷换 ID。

切换账号、API 地址或 Gateway 前，先清理本工具资源。否则无法保证旧资源使用原账号被清理。Build 等待可停止；已经提交的云端构建不会因关闭网页或停止本地等待而撤回。

## 常见问题

- 401：检查 API Key 权限、Gateway 域名、ID 和模板关联关系；envd 流量令牌应由官方 patch 注入。
- Gateway 返回 `sandbox not found`：先查询控制面实例是否存在，再核对 Gateway 与模板。不要把 Gateway 404 直接解释成命令错误。
- `Invalid version: ''`：服务端返回了空 envdVersion。工具保持官网 SDK 与 patch，不伪造版本；保留现场供定位。
- Build 拉取失败：核对镜像地址、客户 SWR 权限、架构和网络。
- OpenClaw 命令找不到：核对实际镜像的 CLI 路径、用户和工作目录。官网 Docker 镜像通常可用 `node /app/dist/index.js`；客户自定义镜像可能安装了 `openclaw` 命令。
- OpenClaw 模型失败：单独检查模型 API Key、Base URL、模型 ID、沙箱出站访问及兼容 API。AgentSphere 鉴权成功不代表模型可用。


### 已有模板与构建版本

环境配置只保留一个已有模板输入框：既可以手动粘贴，也可以加载当前 Gateway 的 Ready 模板后在同一个框中选择。

- 填写 `Template ID:Build ID`：固定使用指定 Ready Build；不存在或未就绪会报错，不自动回退。
- 只填写 `Template ID`：每次新建沙箱前，查询该模板并选取创建时间最新的 Ready Build，组合为 `templateID:buildID` 传入 `Sandbox.create()`。
- 使用现场构建的模板：固定使用本次演示创建的 Build ID。

执行过程会显示实际引用。沙箱资源记录分别保存 Template ID、Build ID 和完整引用，已有沙箱不会因修改来源配置而被静默替换。


### 场景执行参数

“执行用户 user”和“工作目录 cwd”在命令、文件、公网访问、Connect 恢复及恢复后检查文件的能力工作台中设置，不在环境配置表单中设置。每个能力保留独立的页面草稿，点击准备或演示后仅随本次请求生效，不回写全局配置。执行记录保留参数，代码区域同时显示对应的 user / cwd。

用户和目录都必须已在沙箱内存在。参数用于本步骤的准备和执行，不修改模板 Step、startCmd 或 OpenClaw 单独的运行用户。


### Build 日志和 OpenClaw 场景配置

环境准备不再包含日志来源和 OpenClaw 参数。选中“查看 Build 状态与日志”，在工作台填写已有 Template ID 和 Build ID；两项同时留空表示查询本次演示构建。保存仅写入本机配置，不会提交构建或调用模型。

进入“OpenClaw 场景”先填写 CLI、运行用户、模型 Base URL、模型 ID 和模型 API Key，再按准备环境、公网、上传简报、生成、下载、暂停、恢复和清理的业务顺序执行。模型 Key 不回填到页面，留空保留本机已有值。业务流程使用专用沙箱，与基础能力分开；后续步骤不会自动重写资料。[完整场景说明](OPENCLAW.md)。


### 第三步按演示方式展开参数

模板准备方式使用下拉选择，隐藏的参数不随环境表单提交：

- 使用已有模板：只展开模板引用，直接用于新建沙箱。
- 现场构建：只展开镜像、启动 / 就绪命令和规格，后续沙箱固定使用本次 Ready Build；忽略以前保存的已有模板引用。
- 组合演示：展开两组参数，现场提交新 Build，同时用已有 Ready 模板演示沙箱。

保存配置不会自动构建，需在“构建模板”能力中执行。旧配置会自动选择与原先行为一致的模式，用户的本地字段不会丢失。


### 原生存活探针

现场构建参数中可以展开“运行期存活探针”，填写 invoke / livenessProbe 扩展 JSON。新增“存活探针与故障检测”场景使用独立测试资源，不复用业务沙箱进行故障注入。详细步骤和已验证边界见 [LIVENESS.md](LIVENESS.md)。
